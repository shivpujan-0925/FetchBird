FetchBird

High-Speed YouTube Media Downloader & FFmpeg Muxing Pipeline

1. System Architecture Overview

FetchBird is a local-first YouTube media extraction utility. It avoids cloud retention by streaming media directly to local disk buffers, combining video and audio with FFmpeg, and streaming final packages directly to the browser.

2. Layered Architecture

2.1 Presentation Layer

  • Framework: React 18, Vite, TypeScript.
  • Styling: Tailwind CSS v3, Radix UI primitives, Lucide icons.
  • Typography: Plus Jakarta Sans (Headings), Inter (Body), JetBrains Mono (Specs).
  • State & Sockets: TanStack Query for declarative REST fetching; custom useSocket and useMultiSocket hooks for real-time progress.

2.2 Ingress & Realtime Communication

  • HTTP Server: Express 4 with dynamic CORS reflection.
  • WebSockets: Socket.IO v4 with per-job isolated broadcast rooms (io.to(jobId).emit(...)).
  • Production SPA: Single-container deployment where Express serves the compiled React frontend from client/dist.

2.3 Queue & Extraction Pipeline

  • Concurrency Queue: In-memory p-queue worker pool limiting active downloads to prevent CPU and memory exhaustion.
  • Extraction CLI: yt-dlp spawned as child process with Node cipher runtime (--js-runtimes node).
  • Muxing: FFmpeg multiplexes high-bitrate video and audio streams directly into standard .mp4 or converts to 320kbps .mp3.
  • Storage Lifecycle: Automated cleanup scheduler running every 15 minutes purges disk buffer files older than FILE_TTL_MINUTES.

4. API Specifications

Method Endpoint Description Response
POST /api/info Inspect single video metadata & formats { id, title, thumbnail, duration, formats }
POST /api/download Enqueue single video download job { "jobId": string }
POST /api/batch-info Concurrently inspect up to 10 YouTube URLs { "results": [...] }
POST /api/batch-download Enqueue multi-video batch download { "jobs": [...] }
GET /api/status/:jobId Polling status fallback for job { jobId, status, progress, title }
GET /api/file/:jobId Stream final media file with RFC 6266 headers Binary Stream (video/mp4 or audio/mpeg)
GET /health Server liveness probe { "status": "ok" }

5. Database Schema (MongoDB)

interface IJob {
  _id: ObjectId;
  url: string;                  // YouTube URL
  title?: string;              // Sanitized media title
  thumbnail?: string;          // Poster image URL
  formatId: string;            // yt-dlp format selector
  status: "pending" | "downloading" | "merging" | "ready" | "failed";
  progress: number;            // 0 to 100
  filePath?: string;           // Physical storage path
  errorMessage?: string;       // Failure explanation if any
  createdAt: Date;             // Auto-timestamp (TTL indexed)
}
